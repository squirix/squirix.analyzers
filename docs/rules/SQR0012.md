# SQR0012 - Prefer '==' / '!=' over 'is' / 'is not' for null checks

<!-- sources -->
Sources: [PreferEqualityOperatorAnalyzer.cs](../../src/squirix.analyzers/PreferEqualityOperatorAnalyzer.cs)
<!-- sources -->

Prefer the equality operators for null checks; `x == null` and `x != null` read more clearly than `x is null` and
`x is not null`.

The rule only fires when the expression's type resolves to a built-in null operator: reference type, interface
(no user-defined operator is visible through an interface static type, so `==` always binds to reference equality),
nullable value type, or unconstrained generic type parameter. Value-type-constrained type parameters are never
flagged, since the comparison would always be false. Types with user-defined equality operators are never flagged.

A `null` arm inside an `or` pattern is flagged as well; only that arm is reported:

```csharp
// non-compliant
if (ns is null or { IsGlobalNamespace: true })
    return string.Empty;

// compliant
if (ns == null || ns is { IsGlobalNamespace: true })
    return string.Empty;
```

````csharp
// non-compliant
if (value is null)
    return;
if (value is not null)
    return;

// compliant
if (value == null)
    return;
if (value != null)
    return;
````

Severity: **Info**.
