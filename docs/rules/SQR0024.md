# SQR0024 - Prefer a throw-helper method over null-coalescing throw

<!-- sources -->
Sources: [CoalesceThrowHelperAnalyzer.cs](../../src/squirix.analyzers/CoalesceThrowHelperAnalyzer.cs)
<!-- sources -->

Null-coalescing expressions whose right side throws embed the throwing path in the caller, which makes the caller
larger and a worse inlining candidate. Route the throw through a dedicated throw-helper method instead: a small check
plus a non-inlined method that throws. The caller stays small and inlineable, the cold throwing path stays out of it.

`ArgumentNullException` is excluded: it is owned by [SQR0023](SQR0023.md), which names the exact
`ArgumentNullException.ThrowIfNull` replacement. This rule is intentionally project-agnostic and names no helper:
only the consuming codebase knows which exception types deserve one.

```csharp
// non-compliant
_frameBytes = item.FrameBytes ?? throw new InvalidOperationException("Append work item is missing frame bytes.");

// compliant
_frameBytes = item.FrameBytes ?? ThrowMissingFrameBytes(nameof(item.FrameBytes));
```

with the helper defined as a non-inlined method that only throws:

```csharp
[MethodImpl(MethodImplOptions.NoInlining)]
private static byte[] ThrowMissingFrameBytes(string descriptor) =>
    throw new InvalidOperationException($"Append work item '{descriptor}' is missing frame bytes.");
```

Severity: **Info** (escalate to `warning`/`error` in the consuming repository once the codebase is migrated).
