# SQR0023 - Prefer ArgumentNullException.ThrowIfNull over null-coalescing throw

<!-- sources -->
Sources: [CoalesceThrowIfNullAnalyzer.cs](../../src/squirix.analyzers/CoalesceThrowIfNullAnalyzer.cs)
<!-- sources -->

Null-coalescing expressions whose right side throws `ArgumentNullException` should use
`ArgumentNullException.ThrowIfNull` instead. The helper keeps the throwing path out of the caller, which keeps the
caller small and inlineable, while `?? throw` embeds the throw in the caller body.

Only `ArgumentNullException` is flagged; other exception types carry different semantics and have no equivalent
helper. Neither Roslyn (CA1510) nor Rider flag this shape, so this rule closes that gap.

The rule reports only when the guard can be hoisted to a preceding statement without changing behavior:

- the coalesce is the whole value (optionally parenthesized) of a simple assignment statement or a local declaration
  inside a block body;
- the left side is a parameter and the exception is `new ArgumentNullException(nameof(x))` or
  `new ArgumentNullException("x")` with the matching parameter name and no other arguments.

It does not report constructor initializer arguments (`: base(x ?? throw ...)`), field or property initializers,
expression-bodied members, coalesces nested inside a larger expression, or exceptions with a custom message or a
non-matching name, because there is no equivalent statement-level rewrite that preserves them.

```csharp
// non-compliant
_value = value ?? throw new ArgumentNullException(nameof(value));

// compliant
ArgumentNullException.ThrowIfNull(value);
_value = value;
```

Severity: **Info** (escalate to `warning`/`error` in the consuming repository once the codebase is migrated).
