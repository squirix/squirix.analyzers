# SQR0016 - Dispose guard must be accessed through Interlocked or Volatile

<!-- sources -->
Sources: [NoBoolDisposedFieldAnalyzer.cs](../../src/squirix.analyzers/NoBoolDisposedFieldAnalyzer.cs)
<!-- sources -->

An `int` dispose flag must only be mutated via `System.Threading.Interlocked` and observed via `System.Threading.Volatile`,
to avoid torn reads and missing volatile semantics.

````csharp
// non-compliant: direct field access
private int _disposed;

void Dispose() => _disposed = 1;
bool IsDisposed => _disposed != 0;

// compliant
private int _disposed;

void Dispose() => Interlocked.Exchange(ref _disposed, 1);
bool IsDisposed => Volatile.Read(ref _disposed) != 0;
````

The rule applies to an `int` field named exactly `_disposed` (case-sensitive). The field is treated as guarded only when
it is itself the `ref` or `in` operand of an `Interlocked` or `Volatile` call, however it is qualified
(`ref this._disposed`, `ref other._disposed`, `ref Type._disposed`). Parentheses around the operand and a ref
conditional that picks between flags (`ref (first ? ref a._disposed : ref b._disposed)`) count as the operand too. Any
other occurrence, including a read used as another argument of such a call, is reported:

````csharp
// non-compliant: the second _disposed is a plain read
Interlocked.Exchange(ref _disposed, _disposed + 1);
````

Severity: **Warning**.
