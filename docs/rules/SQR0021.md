# SQR0021 - Prefer ArgumentException throw helpers over manual guards

<!-- sources -->
Sources: [UseArgumentExceptionThrowHelperAnalyzer.cs](../../src/squirix.analyzers/UseArgumentExceptionThrowHelperAnalyzer.cs)
<!-- sources -->

Guards that check `string.IsNullOrWhiteSpace` or `string.IsNullOrEmpty` and throw `ArgumentException` should use
`ArgumentException.ThrowIfNullOrWhiteSpace` or `ArgumentException.ThrowIfNullOrEmpty` instead. The helper keeps the
throwing path out of the caller, which keeps the caller small and inlineable.

Only guards that throw a plain `ArgumentException` are flagged (`ArgumentNullException` and
`ArgumentOutOfRangeException` have their own helpers). `switch` arms cannot use a throw helper and are never flagged.
The thrown `ParamName` is matched by constructor parameter, not by argument position, so named and reordered arguments
are handled: a guard is flagged only when its `paramName` argument (a string literal or `nameof`) names the guarded
variable, or when the `paramName` value is not a literal or `nameof`.

The helper names the parameter after the text of its argument. When that text is not the name the guard throws, as
with `options.Name`, `options?.Name` or `args[0]` and a name such as `nameof(options.Name)`, the message says to pass
the name as the second argument, so that `ParamName` stays `"Name"` and does not become `"options.Name"`:

```csharp
ArgumentException.ThrowIfNullOrEmpty(options.Name, nameof(options.Name));
```

This is the build-time mirror of the Rider inspections `UseThrowIfNullMethod` /
`UseArgumentExceptionThrowIfMethod`, which are IDE-only.

```csharp
// non-compliant
if (string.IsNullOrWhiteSpace(value))
    throw new ArgumentException("Value is required.", nameof(value));

// compliant
ArgumentException.ThrowIfNullOrWhiteSpace(value);
```

Severity: **Info** (escalate to `warning`/`error` in the consuming repository once the codebase is migrated).
