# SQR0011 - Avoid redundant default argument values

<!-- sources -->
Sources: [RedundantDefaultArgumentAnalyzer.cs](../../src/squirix.analyzers/RedundantDefaultArgumentAnalyzer.cs)
<!-- sources -->

Omit arguments that equal the parameter default. Passing the default explicitly is redundant, and the default may change
at the declaration — keeping it implicit makes the call robust to such changes.

````csharp
public void Configure(int retries = 3, bool failFast = false) { }

// non-compliant
Configure(retries: 3, failFast: false);

// compliant
Configure();
````

The rule only reports when the argument can be dropped without changing which method is bound. A named argument is
reported on its own. A positional argument can go only together with everything after it, since dropping it alone
would hand the next argument to its parameter, so trailing positional defaults are reported once, as one run that
starts at the first of them:

````csharp
void Configure(int port, int retries = 3, int delay = 5) { }

// one finding on "3, 5": omit both, or neither
Configure(80, 3, 5);
````

Target-typed `new(...)` is covered as well. Parameters marked `[CallerMemberName]`, `[CallerFilePath]`,
`[CallerLineNumber]` or `[CallerArgumentExpression]` are never reported, because omitting the argument makes the compiler
substitute caller information instead of the default value.

Severity: **Info**.
