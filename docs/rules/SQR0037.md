# SQR0037 - Do not read the system clock when a TimeProvider is available

<!-- sources -->
Sources: [ClockBypassesTimeProviderAnalyzer.cs](../../src/squirix.analyzers/ClockBypassesTimeProviderAnalyzer.cs),
[SystemClockFacts.cs](../../src/squirix.analyzers/SystemClockFacts.cs)
<!-- sources -->

Code that has a `TimeProvider` and still reads the system clock keeps running on real time when a test supplies its
own provider.

The rule reports these reads:

- `TimeProvider.System`;
- `DateTime.Now`, `DateTime.UtcNow`, `DateTimeOffset.Now`, `DateTimeOffset.UtcNow`;
- `Environment.TickCount`, `Environment.TickCount64`.

A read is reported only when the code at that place can use a `TimeProvider`, or a type derived from it:

- a parameter of the containing method, constructor, indexer, local function or lambda, or a primary constructor
  parameter;
- a field or property of the containing type, or a non-private one of a base type.

A static member does not see instance members, and a static lambda or local function does not see the parameters
around it. The message names the provider that was found.

Not reported: a comparison with `TimeProvider.System`, a `nameof` operand, the declaration of the provider itself, and
the places that [SQR0036](SQR0036.md) reports.

````csharp
class Worker
{
    private readonly TimeProvider _clock;

    public Worker(TimeProvider clock)
    {
        _clock = clock;
    }

    // non-compliant
    public DateTimeOffset Started() => DateTimeOffset.UtcNow;

    public Task Wait(TimeSpan delay) => Task.Delay(delay, TimeProvider.System);

    // compliant
    public DateTimeOffset Started() => _clock.GetUtcNow();

    public Task Wait(TimeSpan delay) => Task.Delay(delay, _clock);
}
````

Severity: **Warning**.
