# SQR0039 - Do not default a logger dependency to a null logger

<!-- sources -->
Sources: [NoNullLoggerDefaultAnalyzer.cs](../../src/squirix.analyzers/NoNullLoggerDefaultAnalyzer.cs),
[DependencyDefaultFacts.cs](../../src/squirix.analyzers/DependencyDefaultFacts.cs)
<!-- sources -->

A logger is a dependency. When it falls back to a null logger, a caller that forgets to pass one loses every log
entry of that type without any error.

The rule reports `NullLogger.Instance`, `NullLogger<T>.Instance` and `NullLoggerFactory.Instance` where they are the
value of a dependency the caller did not supply:

- the right side of `??` or `??=`;
- the initializer of an instance field or property;
- an argument of a `this(...)` or `base(...)` constructor initializer;
- the value assigned to an instance field or property of the containing type.

Passing a null logger as an argument of a call or setting it in an object initializer is not reported: there the
calling code names it explicitly, as a test does. A nullable or optional logger parameter is not reported on its own.

````csharp
// non-compliant
class Worker
{
    private readonly ILogger _log;

    public Worker(ILogger<Worker>? log = null)
    {
        _log = log ?? NullLogger<Worker>.Instance;
    }
}

// compliant
class Worker
{
    private readonly ILogger _log;

    public Worker(ILogger<Worker> log)
    {
        _log = log;
    }
}
````

Severity: **Warning**.
