# SQR0036 - Do not default a TimeProvider dependency to the system clock

<!-- sources -->
Sources: [NoSystemClockDefaultAnalyzer.cs](../../src/squirix.analyzers/NoSystemClockDefaultAnalyzer.cs),
[DependencyDefaultFacts.cs](../../src/squirix.analyzers/DependencyDefaultFacts.cs)
<!-- sources -->

A type that takes a `TimeProvider` can run on a test clock. When the dependency falls back to `TimeProvider.System`,
a caller that forgets to pass the provider gets the system clock without any error, and a test that meant to control
time does not.

The rule reports `TimeProvider.System` where it is the value of a dependency the caller did not supply:

- the right side of `??` or `??=`;
- the initializer of an instance field or property;
- an argument of a `this(...)` or `base(...)` constructor initializer;
- the value assigned to an instance field or property of the containing type.

Passing `TimeProvider.System` as an argument of a call or setting it in an object initializer is not reported: there
the calling code names the clock explicitly. The initializer of a static field or property is not reported either.

````csharp
// non-compliant
class Worker
{
    private readonly TimeProvider _clock;

    public Worker(TimeProvider? clock = null)
    {
        _clock = clock ?? TimeProvider.System;
    }
}

// compliant
class Worker
{
    private readonly TimeProvider _clock;

    public Worker(TimeProvider clock)
    {
        _clock = clock;
    }
}
````

Severity: **Warning**.
