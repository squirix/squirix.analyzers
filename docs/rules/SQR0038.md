# SQR0038 - Filter a cancellation catch by the cancellation token

<!-- sources -->
Sources: [CancellationCatchFilterAnalyzer.cs](../../src/squirix.analyzers/CancellationCatchFilterAnalyzer.cs)
<!-- sources -->

A method that takes a `CancellationToken` and catches `OperationCanceledException` without a filter handles every
cancellation the same way: the one its caller requested and any other, for example an inner timeout or a token of a
dependency. A background service written this way treats a cancellation the host did not request as a normal shutdown
and ends silently.

The rule reports a `catch (OperationCanceledException)` or `catch (TaskCanceledException)` clause when both hold:

- a function around it (method, constructor, local function or lambda) has a `CancellationToken` parameter;
- neither its `when` filter nor its body reads a `CancellationToken` or a `CancellationTokenSource`.

Any such read is accepted: `token.IsCancellationRequested`, its negation, `error.CancellationToken == token`, a check
of a token source the method created, or a body that passes the tokens to code that tells the cancellations apart. A
catch that ends with `throw` is not reported, and neither is a catch in a function without a `CancellationToken`
parameter.

````csharp
// non-compliant
protected override async Task ExecuteAsync(CancellationToken stoppingToken)
{
    try
    {
        await RunAsync(stoppingToken);
    }
    catch (OperationCanceledException)
    {
    }
}

// compliant
protected override async Task ExecuteAsync(CancellationToken stoppingToken)
{
    try
    {
        await RunAsync(stoppingToken);
    }
    catch (OperationCanceledException) when (stoppingToken.IsCancellationRequested)
    {
    }
}
````

Severity: **Info**.
