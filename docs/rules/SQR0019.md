# SQR0019 - Avoid allocating exception assert invocations

<!-- sources -->
Sources: [NoAllocatingThrowsAssertAnalyzer.cs](../../src/squirix.analyzers/NoAllocatingThrowsAssertAnalyzer.cs)
<!-- sources -->

Exception asserts that capture the operation in a delegate (xUnit `Assert.Throws`, FluentAssertions
`Should().Throw`, NUnit `Assert.Throws`, and similar `Throws`/`Throw` helpers) allocate a display class on every call
when passed a lambda or anonymous method. Avoid them in allocation-sensitive test code.

Flag a `Throws`/`Throw` family invocation only when at least one argument is a lambda or anonymous method — a delegate
capture. A method reference passed without a delegate literal does not allocate a display class and is allowed.

Prefer an allocation-free assert that takes an already-started operation instead of wrapping it in a delegate.

````csharp
// non-compliant: delegate capture allocates on every call
Assert.Throws<InvalidOperationException>(() => operation());

// non-compliant: FluentAssertions-style lambda capture
action.Should().Throw<InvalidOperationException>(() => operation());

// compliant: pass the already-started operation instead of wrapping a delegate
await MyThrows.ThrowsAsync<InvalidOperationException>(operationAsync());
````

Severity: **Warning**.
