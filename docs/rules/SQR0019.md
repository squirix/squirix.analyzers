# SQR0019 - Avoid allocating exception assert invocations

<!-- sources -->
Sources: [NoAllocatingThrowsAssertAnalyzer.cs](../../src/squirix.analyzers/NoAllocatingThrowsAssertAnalyzer.cs)
<!-- sources -->

Exception asserts that capture the operation in a delegate (xUnit `Assert.Throws`, FluentAssertions
`Should().Throw`, NUnit `Assert.Throws`, and similar `Throws`/`Throw` helpers) allocate a display class on every call
when passed a capturing lambda or anonymous method. Avoid them in allocation-sensitive test code.

Flag a `Throws`/`Throw` family invocation only when it is given a capturing lambda or anonymous method — a delegate
that captures outer state or `this`. A non-capturing lambda has no closure, is cached as a single static delegate
(whether or not it is marked `static`), and does not allocate per call. A method group passed without a lambda or
anonymous method is not analyzed by this rule; note that an instance method group still allocates a delegate on every
call.

The delegate is looked for in the arguments of the assert itself and of every earlier call of the same chain, which
is where the fluent libraries take it:

````csharp
// non-compliant: TUnit takes the delegate in That(...)
await Assert.That(() => cache.Get(key)).Throws<InvalidOperationException>();

// non-compliant: FluentAssertions takes it in Invoking(...) or Awaiting(...)
FluentActions.Invoking(() => cache.Get(key)).Should().Throw<InvalidOperationException>();
````

The family is `Throws`, `ThrowsAny`, `ThrowsExactly`, `ThrowsException`, `Throw`, `ThrowAny`, `ThrowExactly` and their
`Async` forms, plus `ThrowWithinAsync`. A call by a bare name is an assert when it comes from another type through
`using static` (`using static Xunit.Assert; Throws<T>(() => ...)`); a method of the enclosing type or of its base
with such a name is the code's own helper and is not reported.

Not reported:

- a delegate held in a variable (`Action act = () => ...; act.Should().Throw<T>();`): it is created where the variable
  is assigned, and the assert only receives it;
- a lambda that becomes an expression tree, as in a mock setup (`mock.Setup(c => c.Get(key)).Throws<T>()`);
- the NUnit constraint form `Assert.That(() => ..., Throws.InvalidOperationException)`, where the assert is `That`.

Prefer an allocation-free assert that takes an already-started operation instead of wrapping it in a delegate.

````csharp
// non-compliant: capturing lambda allocates on every call
Assert.Throws<InvalidOperationException>(() => operation());

// compliant: non-capturing lambda is cached and does not allocate per call
Assert.Throws<InvalidOperationException>(() => StaticHelper());

// non-compliant: FluentAssertions-style lambda capture
action.Should().Throw<InvalidOperationException>(() => operation());

// compliant: pass the already-started operation instead of wrapping a delegate
await MyThrows.ThrowsAsync<InvalidOperationException>(operationAsync());
````

Severity: **Warning**.
