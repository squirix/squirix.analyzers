# SQR0034 - Avoid global using directives

<!-- sources -->
Sources: [NoGlobalUsingAnalyzer.cs](../../src/squirix.analyzers/NoGlobalUsingAnalyzer.cs)
<!-- sources -->

Namespace dependencies must be visible in each file. A `global using` directive hides the dependency from every file of
the project, which makes reviews and package boundary checks harder.

The rule also reports the global usings the build generates into `<Project>.GlobalUsings.g.cs`. They come from
`ImplicitUsings` or from a package switch such as `TUnitImplicitUsings`. The fix is to disable that property and add
explicit `using` directives to the files that need them.

````csharp
// non-compliant
global using System;

// non-compliant: generated by <ImplicitUsings>enable</ImplicitUsings>
// <auto-generated/>
global using System.Collections.Generic;

// compliant: explicit directive in the file that needs it
using System;
````

Severity: **Warning**.
