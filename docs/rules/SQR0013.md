# SQR0013 - Prefer '==' over 'is' for constant values

<!-- sources -->
Sources: [PreferEqualityOperatorAnalyzer.cs](../../src/squirix.analyzers/PreferEqualityOperatorAnalyzer.cs)
<!-- sources -->

Constant-value comparison reads more clearly with the `==` operator than with an `is` pattern. Prefer `x == constant`
over `x is constant`.

The rule does not fire for `float.NaN` / `double.NaN`, because equality operators never match NaN while constant
patterns do.

The rule only fires when `==` is a plain value comparison equivalent to the pattern: the input is a built-in
primitive or `string` (or `Nullable<>` of one) compared with a built-in constant, or an enum (or `Nullable<>` of it)
compared with a constant of the same enum. It does not fire for inputs typed `object`, interfaces such as
`IComparable`, `Enum`, `ValueType`, `Span<T>` / `ReadOnlySpan<T>`, or unconstrained type parameters, where `==` either
does not compile or compares references or memory identity instead of values.

Constants inside an `or` pattern are not flagged: `x is 1 or 2` would need `x == 1 || x == 2`, which evaluates `x`
twice. Only `null` arms of an `or` pattern are reported, by SQR0012.

````csharp
// non-compliant
if (status is 200)
    return;

// compliant
if (status == 200)
    return;
````

Severity: **Info**.
