# SQR0022 - Prefer a throw-helper method for TimeSpan range guards

<!-- sources -->
Sources: [UseTimeSpanThrowHelperAnalyzer.cs](../../src/squirix.analyzers/UseTimeSpanThrowHelperAnalyzer.cs)
<!-- sources -->

Guards that compare a value against `TimeSpan.Zero` and throw `ArgumentOutOfRangeException` should route the throw
through a throw-helper method instead of an inline `if` check with `throw`. The helper keeps the throwing path out
of the caller, which keeps the caller small and inlineable.

The BCL `ArgumentOutOfRangeException.ThrowIf*` helpers cannot be used here: they require `INumberBase<T>`, which
`TimeSpan` does not implement. Write a small project helper instead — an inlineable check over a non-inlined method
that throws:

```csharp
// non-compliant
if (value <= TimeSpan.Zero)
    throw new ArgumentOutOfRangeException(nameof(value), value, "Must be positive.");

// compliant
value.ThrowIfNegativeOrZero(nameof(value), "Must be positive.");
```

with the helper defined as:

```csharp
[MethodImpl(MethodImplOptions.AggressiveInlining)]
internal static void ThrowIfNegativeOrZero(this TimeSpan value, string paramName, string? message = null)
{
    if (value <= TimeSpan.Zero)
        ThrowNegativeOrZero(value, paramName, message ?? "Value must be greater than zero.");
}

[MethodImpl(MethodImplOptions.NoInlining)]
private static void ThrowNegativeOrZero(TimeSpan value, string paramName, string message) =>
    throw new ArgumentOutOfRangeException(paramName, value, message);
```

Numeric-constant comparisons are CA1512 territory and are not flagged here; only `TimeSpan.Zero` comparisons, which
CA1512 does not recognize, are considered. `switch` arms cannot use a throw helper and are never flagged.

Severity: **Info** (escalate to `warning`/`error` in the consuming repository once the codebase is migrated).
