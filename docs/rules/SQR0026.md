# SQR0026 - Simplify if-return to conditional return

<!-- sources -->
Sources: [SimplifyIfReturnAnalyzer.cs](../../src/squirix.analyzers/SimplifyIfReturnAnalyzer.cs)
<!-- sources -->

An `if` statement without `else` whose body is a single `return` or `throw` immediately followed by another
`return` or `throw` should be simplified to one conditional return, using a throw expression where needed. This keeps
the two complementary outcomes in one place.

Only value-returning `return` statements and `throw` statements with an explicit expression are considered, at
least one side must be a `return`, and `ref` returns are never flagged, so the rewrite never changes behavior.

This rule backports the newer `IDE0046` detections for SDK 10-era compilers, which stay silent on several of these
shapes (for example an `if` return followed by a ternary return). On SDK 11 and later the two rules overlap on the
same spans; consumers should keep only one of them enabled.

```csharp
// non-compliant
int Sign(int value)
{
    if (value < 0)
    {
        return -1;
    }

    return value;
}

// compliant
int Sign(int value)
{
    return value < 0 ? -1 : value;
}
```

```csharp
// non-compliant
string Require(string? value, string paramName)
{
    if (value == null)
        throw new ArgumentNullException(paramName);

    return value;
}

// compliant
string Require(string? value, string paramName)
{
    return value == null ? throw new ArgumentNullException(paramName) : value;
}
```

Severity: **Warning**.
