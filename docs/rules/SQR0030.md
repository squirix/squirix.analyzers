# SQR0030 - Await tasks that use a resource before its using scope ends

<!-- sources -->
Sources: [TaskOutlivesUsingScopeAnalyzer.cs](../../src/squirix.analyzers/TaskOutlivesUsingScopeAnalyzer.cs)
<!-- sources -->

A resource declared by `using` or `await using` is disposed when its scope ends. A task started with that resource
and not awaited inside the scope is still running at that point, so it operates on a disposed object and fails with
`ObjectDisposedException` or corrupts state. Returning the task from a non-async method has the same effect: the
caller receives the task only after the `using` scope has already disposed the resource.

The scope is the body of a `using` statement, or the statements that follow a `using` declaration in the enclosing
block. The rule tracks the declared locals and local aliases of them (`var token = cts.Token;`). A call or object
creation of type `Task`, `Task<T>`, `ValueTask` or `ValueTask<T>` is bound to the resource when its receiver or any
argument references the resource or an alias, including inside nested argument expressions. A local assigned from
such a call is tracked too, and a task-returning call that takes that local as an argument (`Task.WhenAny(a, b)`) is
bound as well.

The rule reports a bound task that is a fire-and-forget statement (`stream.CopyToAsync(destination);` or
`_ = stream.FlushAsync();`), is returned, or is held in a local that is returned. The fix is to `await` the task
inside the scope.

## What is not reported

- a task that is awaited, directly or through `.ConfigureAwait(...)`, or passed to a call that is awaited in the
  scope (`await Task.WhenAll(a, b)`);
- code inside lambdas, anonymous methods and local functions: it runs on its own schedule, and a using scope inside
  it is analyzed on its own;
- a task that does not reference the resource;
- `yield return`;
- a `using (expression)` without a declared local, because there is no resource variable to track;
- a value of primitive, string, enum or array type derived from the resource in an argument or alias initializer
  (`stream.Length`, `stream.ToArray()`, `Parse(stream)`, `SHA256.HashData(stream)`): such a value cannot carry the
  resource, at any nesting depth of the argument. A receiver chain rooted at the resource
  (`connection.CreateCommand().ExecuteNonQueryAsync()`) always counts;
- finished-task factories: `Task.FromResult`, `Task.FromException`, `Task.FromCanceled`, the `ValueTask` equivalents
  and the `ValueTask` / `ValueTask<T>` constructors, because the task is already complete;
- a task stored into a field, property or collection: only fire-and-forget statements, `return` statements and returned
  task locals are reported;
- a local reassigned to a value that is not rooted at the resource: it stops being an alias, so
  `token = CancellationToken.None;` followed by `Task.Delay(1, token)` is clean;
- a task local on which `.Wait()`, `.Result` or `.GetAwaiter().GetResult()` is used, which is treated like `await`.

## What is tracked

- The receiver chain of a call, its arguments, and a lambda or anonymous method passed as an argument that captures the
  resource (`Task.Run(() => stream.WriteByte(1))`) bind the call to the resource. Other lambda bodies are not analyzed.
- A local initialized or assigned from a member chain rooted at the resource (`var token = cts.Token;`), or from a call
  or object creation bound to the resource whose type can carry it (`var reader = new StreamReader(stream);`), is an
  alias.
- `?.` calls, both branches of `?:`, both operands of `??`, switch expression arms, casts and `!` are looked through, and
  the inner bound call is reported.
- A `using` declaration labeled with `L:` scopes over the following statements of the enclosing block.

## Limitations

- An `await` clears the tracking of every task local mentioned in its operand from that point on, regardless of
  control flow, so an `await` in one branch also clears the local for the other branch.
- An un-awaited statement ending in `.ConfigureAwait(...)` is not reported, because its type is not a task.
- When a task references resources of nested using scopes, it is reported once, naming the innermost resource.

```csharp
// non-compliant
using var source = File.OpenRead(path);
return source.CopyToAsync(destination);

// compliant
await using var source = File.OpenRead(path);
await source.CopyToAsync(destination);
```

Severity: **Warning**.
