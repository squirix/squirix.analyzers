# SQR0020 - Merge duplicate catch blocks with identical bodies

<!-- sources -->
Sources: [MergeDuplicateCatchBlocksAnalyzer.cs](../../src/squirix.analyzers/MergeDuplicateCatchBlocksAnalyzer.cs)
<!-- sources -->

Consecutive `catch` blocks that catch different exception types with identical bodies should be combined into a single
`catch` clause with a `when` filter pattern. This keeps the duplicated handler body in one place.

Only clauses that declare an exception type, have no `when` filter, and do not reference their exception variable in the
body are considered, so the merge never changes behavior. A conditional directive (`#if`, `#elif`, `#else`, `#endif`) in a
clause or between two clauses ends the run: such clauses are not the same in every configuration.

````csharp
// non-compliant
try
{
    Work();
}
catch (IOException)
{
    HandleFailure();
}
catch (ObjectDisposedException)
{
    HandleFailure();
}

// compliant
try
{
    Work();
}
catch (Exception ex) when (ex is IOException or ObjectDisposedException)
{
    HandleFailure();
}
````

A clause whose type derives from the type of another clause of the run is left out of the pattern, since that other
clause already catches its exceptions. When one type is left, the rule says to keep only its clause:

````csharp
// non-compliant: the second clause handles an IOException the same way
catch (IOException)
{
    HandleFailure();
}
catch (Exception)
{
    HandleFailure();
}

// compliant
catch (Exception)
{
    HandleFailure();
}
````

Severity: **Warning**.
